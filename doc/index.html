About Uranium

Uranium is a modern, high-performance, stack-based bytecode programming language designed for ultimate execution speed, small runtime footprint, and multi-platform versatility. It merges the ergonomics of modern high-level languages with the extreme speed of a native compilation pipeline.

⚡ Core Highlights

Uranium features a multi-architecture JIT compiler compiling hot paths directly into machine code, a low-latency Tri-color Incremental Garbage Collector, and a powerful C Programming API (UCPAPI) for native library FFI.

Getting Started

Uranium uses an independent build orchestrator called OMake alongside traditional CMake configurations.

Compilation

To compile Uranium from sources with maximum parallel execution and zero warnings:

# Using OMake with debug preset
.\omake\omake.exe --preset debug --build

# Using OMake with release preset (high optimization)
.\omake\omake.exe --preset release --build

Execution

Run files using the compiled interpreter binary:

./bin/uranium main.ur

Variables & Types

Uranium supports dynamic typing with explicit promotions for performance critical operations. Variables are defined using the let keyword.

let integerVar = 100       // VAL_INT (64-bit signed integer)
let floatVar = 3.14        // VAL_NUMBER (double)
let stringVar = "Uranium"  // VAL_STRING (string)
let boolVar = true         // VAL_BOOL (boolean)
let arrayVar = [1, 2, 3]   // VAL_ARRAY (dynamic array)
let mapVar = map()         // VAL_MAP (dictionary)

Control Flow

Control flow structures use traditional C-like blocks with dynamic expression evaluations.

If-Else Conditions

let score = 85
if (score >= 90) {
    print("Excellent")
} elif (score >= 70) {
    print("Pass")
} else {
    print("Fail")
}

For Loops

for (let i = 0, i < 10, i = i + 1) {
    print("Iteration: " + str(i))
}

Functions

Functions are defined using the fn keyword and support closure scopes and parameter type annotations.

fn calculateArea(width, height) {
    return width * height
}

// Function call
let area = calculateArea(10, 20)

Classes & OOP

Uranium features class-based object-oriented programming with constructors, properties, and methods.

class Player() {
    fn init(name, score) {
        this.name = name
        this.score = score
    }

    fn incrementScore(val) {
        this.score = this.score + val
    }
}

let player = Player("Alice", 100)
player.incrementScore(50)
print(player.score) // 150

Native JIT Compiler

Uranium features an independent, multi-architecture Native JIT compiler designed from scratch with no external assembler libraries. When a bytecode function gets hot (32 invocations), the JIT compiles it into raw machine instructions.

Supported Architectures

Platform Architecture Backend Module
Windows x86, x64, ARM32, ARM64 native_jit_x64, native_jit_arm64, etc.
Linux x86, x64, ARM32, ARM64 native_jit_x64, native_jit_arm64, etc.
macOS Intel x64, Apple Silicon ARM64 native_jit_x64, native_jit_arm64

Hardened Security Management

For macOS Apple Silicon, Uranium utilizes specialized JIT protection page switches to strictly comply with W^X security policies:

// macOS Apple Silicon mapping and toggling
flags |= MAP_JIT;
pthread_jit_write_protect_np(0); // Write mode
// ... write bytes ...
pthread_jit_write_protect_np(1); // Execute mode
__builtin___clear_cache(start, end); // Clear instruction cache

Tri-color Incremental Garbage Collector

To eliminate stop-the-world latency spikes, Uranium utilizes a Generational Tri-color Incremental Garbage Collector. The garbage collection passes are interleaved directly into the VM execution budget loop.

Color Status Definitions

  • White (Unvisited): Objects that are candidates for collection.
  • Grey (Discovered): Objects that are visited, but their children/dependencies are yet to be scanned.
  • Black (Preserved): Verified live objects that will not be swept in the current step.

Execution Stepping

// Inside VM execution loop (vm.cpp)
int instructionBudget = 512;
while (instructionBudget-- > 0) {
    uraniumHeap().collectGarbageStep(2); // Runs small GC incremental step
    // ... run bytecode ...
}

UCPAPI & System Input

The FFI module (UCPAPI) allows dynamic loading of native dynamic libraries, while standard system functions provide Console Input capabilities.

Console Input

Read lines from the standard input stream (stdin) using the built-in input() function:

// Read username with a prompt message
let name = input("Enter your name: ")
print("Hello, " + name)

UCPAPI Example Usage

import ucpapi

// Load dll
let lib = ucpapi.load("C:/path/to/library.dll")

// Invoke function
let result = lib.call("my_c_function", 10, 20)

std.collections

Standard library collections provide optimized data structures in urlib/std/collections.ur.

import std as std

// 1. Set
let activeUsers = std.Set()
activeUsers.add("user1")

// 2. Queue
let taskQueue = std.Queue()
taskQueue.enqueue("task1")

// 3. Stack
let actionStack = std.Stack()
actionStack.push("action1")

// 4. BigInt
let bigVal = std.BigInt("9999999999999999999999")

Native GUI API

Uranium provides native GUI rendering functions backed by direct Win32 and system windowing APIs.

// Create window
let winId = guiCreateWindow("My Window", 600, 600)
guiCenterWindow(winId)

// Add components
let lbl = guiAddLabel(winId, "Status: OK", 20, 20, 150, 30)
let btn = guiAddButton(winId, "Click Me", 20, 60, 100, 40)

guiShowWindow(winId)
